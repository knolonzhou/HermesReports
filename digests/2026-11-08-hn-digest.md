### 1. Libghostty 1.0：终端模拟器终于有了"通用发动机"（937 分 / 156 评论）

**背景**：终端模拟器（Terminal Emulator，就是那个黑窗口程序）看着简单，其实巨难写——它要把程序输出的一堆转义字符（ANSI escape codes，控制颜色/光标/图形的特殊字节序列）实时翻译成屏幕画面，还要兼容几十年积累的各种协议。过去每个 IDE、每个云厂商都得自己造一个，质量参差不齐。

**发生了什么**：Mitchell Hashimoto（HashiCorp 创始人、Ghostty 终端作者）宣布 [libghostty 1.0](https://mitchellh.com/writing/libghostty-1-0)——把 Ghostty 的核心拆成一个独立的 C 库，1.0 意味着 ABI（Application Binary Interface，二进制层面的接口约定，稳定了别人编译好的程序就不会因为库升级而崩）正式冻结。最震撼的是采用名单：JetBrains 全家桶（IntelliJ/PyCharm/GoLand）的内置终端已经换成了它，覆盖 1250 万活跃用户；Neovim 的替换 PR 已批准，顺手关掉了[一个 10 年没人修的老 bug](https://github.com/neovim/neovim/issues/4997)；KDE 在拿它做 Konsole 替代品；Vercel 的 Turborepo、OrbStack 也在用。作者还实测：一台 4 核 8GB 的服务器同时跑 10000 个活跃终端没问题——反而是 bash 太吃内存先撑不住。

**为什么值得看**：这是"基础设施去重复化"的教科书案例——一个团队把最难的 20% 做好，全行业白嫖。现在用约 1500 行 C 代码就能造出一个功能超过 2025 年几乎所有终端的终端。

**评论区两边**：**A 方（赞叹派）**认为在"万物永远 0.x"的时代，一个知名项目敢发 1.0 并承诺 ABI 稳定是稀缺品质，"感觉 libghostty 昨天才宣布，今天 Emacs 插件都比原有方案强了"；**B 方（追问派）**的代表问题是 swyx 的："为什么大家还在造自己的终端？深层痛点到底是什么？"——另一批人则抱怨 Windows 版 Ghostty 依然没有官方支持（只能靠第三方移植或 Windows Terminal），还有人纠结"为什么是 C 而不是 Zig"（答案：Zig 写的，但导出 C ABI）。

### 2. 让便宜模型学会"求助"：Jev + Opus 混合方案，准确率追平 Opus、成本 1/4（552 分 / 136 评论）

**背景**：数据公司 Hightouch 日常要干一件苦活：身份解析（Identity Resolution，把数据库里"张三/张3/zhangsan@xx"这类记录判断是不是同一个人）的质量审查。传统靠人工抽查，一小时才 50 条；用最强的大模型（如 Claude Opus）自动审，准确率 99% 但每千条要 $3.86。市面上新出现了一类"决策模型"（Decision Model，如 Jev、GPT-6 Luna——专门回答"这个条件成不成立"并给出 0-1 置信度的小模型），每千条只要 $0.05-0.10，便宜 90 倍、快 10 倍以上。

**发生了什么**：Hightouch 做了个[对照实验](https://hightouch.com/blog/llm-judges-identity-resolution)：用模拟小镇数据造了 1000 个身份（一半正常、一半是"过度合并"错误），让各种模型来判。结果便宜模型单独用能到 95-97%，但难题上掉队。关键洞察是 **Jev 的置信度校准得好**——它答错时大多自己也"心虚"（低置信度），而 Luna 错了还自信满满。于是方案变成：Jev 先判，置信度不够就升级问 Opus。最终混合方案准确率≈Opus 单干，总成本降到 1/4 以下。

**为什么值得看**：这是"级联推理"（cascade，便宜模型打头阵、难题才叫贵的）落地的漂亮样本，对所有用 LLM 做大批量判断的团队都有直接参考价值——校准好的置信度比绝对准确率更值钱。

**评论区两边**：**A 方（实战派）**纷纷现身说法："我们安全工程早这么干了""我用 Qwen3.8-27B 当编排器指挥 Opus，效果更好还更便宜"，并预言决策模型管理上下文是未来；**B 方（泼冷水派）**质疑：动态挑上下文会毁掉 prompt 缓存命中率（缓存按前缀匹配，内容一变就失效），成本账没那么简单；还有人吐槽这类"小模型+大模型兜底"说穿了就是 if-else 的高级版。

### 3. 极品飞车地下狂飙 2 在浏览器里复活（547 分 / 166 评论）

**背景**：《Need for Speed: Underground 2》是 EA 2004 年的街头赛车游戏，公认系列巅峰之一，但因音乐版权到期等原因已**在所有商店下架**，正版都买不到。nfsu2.xyz 用 WebAssembly（WASM，把原生代码编译成浏览器能直接跑的字节码）+WebGPU 把整个游戏搬进了网页，还加了联机自由漫游、名字认领等新功能。

**发生了什么**：打开网页就能玩，手机也行——评论区有人晒 iPhone 14 满帧、M2 MacBook Air 上 Firefox 流畅运行；当然也有人抱怨要开 Chrome 的 `enable-unsafe-webgpu` 实验开关、加载资源时掉帧。游戏本体+素材都托管在站上，这在法律上是明确的灰色（黑色）地带。

**为什么值得看**：这是"游戏保存"（game preservation，老游戏因版权/服务器关闭而永久消失的对抗行动）与浏览器技术成熟度的一次同框展示——WASM 跑复杂 3D 游戏已经基本可用（尽管 GC 停顿等老问题还在）。

**评论区两边**：**A 方（法律洁癖派）**问"这怎么合法的？"（自答：不合法），担心这类项目会招致大厂打击、反而毁了游戏保存的未来，经验法则是"挂了广告的死得最快，低调的活得久"；**B 方（无所谓派）**反驳："偷一个游戏你是海盗，偷一千个游戏你是 OpenAI/Anthropic/谷歌"——大公司训练 AI 用尽版权素材没人管， abandoned 的老游戏被爱好者复活反而要被追究？还有人指出这游戏本来就买不到了，"没有任何人受到损害"。

### 4. 每台 Mac 都自带一个没写进文档的"家人识别器"（435 分 / 249 评论）

**背景**：Apple Intelligence（苹果的端侧 AI 系统）宣传卖点是"数据不出设备"。但没人知道它到底在本地存了什么——直到研究者翻出 `~/Library/IntelligencePlatform` 目录。

**发生了什么**：8rank.ai 的研究者发文披露：macOS 会基于你的照片、信息等数据在本地构建一张**个人知识图谱**（Personal Knowledge Graph，把"人-事-物"及其关系存成网状数据的结构），其中包含一个没有任何文档的"家庭成员分类器"——它会推断"这个人是你的妈妈/配偶/孩子"，并给每条事实附上置信度。作者还开源了 [iKnow 工具](https://github.com/8rank/iKnow)让任何人检查自己 Mac 里的图谱。作者承认：数据理论上不出本机（受 TCC 完全磁盘访问权限保护），但 Apple Intelligence 模型可以查询它，且苹果对这套系统"接近零文档"。

**为什么值得看**：这是"端侧 AI 隐私"宣传与现实之间的一次硬对撞——即使数据不上云，你的电脑也在替你做你没同意过的亲属关系推断，而且没有开关、没有说明。

**评论区两边**：**A 方（警觉派）**炸锅："如果我 Mac 真在干这个我会非常生气""能不能集体诉讼？"，高赞评论总结出一条定律："时间线拉得够长，所有闭源软件都会变成间谍软件"；还有人指出既然 Apple Intelligence 能查这个图谱，"离被 prompt 注入（提示注入，恶意内容诱导 AI 泄露信息）就只差一步"。**B 方（淡定派）**反驳：数据留在本地磁盘，Meta 的数据仓库里存着比这多一千倍的同类信息，"只要不出设备我无所谓"——真正的问题不是收集，而是没文档、没法关。另有一条支线骂声：不少人批评这篇文章本身是 AI 写的（"文风中途从人变成 LLM 非常明显"），作者被喷得只能在评论区反复答疑。

### 5. Firecracker 虚拟机逃逸：从 microVM 内部打到宿主机 root（274 分 / 117 评论）

**背景**：Firecracker 是 AWS 开源的 microVM（微虚拟机）引擎——Lambda、Fargate 这些"无服务器"产品的每段用户代码都跑在一个 Firecracker 小虚拟机里，靠它把不可信代码和宿主机隔开。虚拟化逃逸（VM escape，从虚拟机内部打穿隔离控制宿主机）是这个领域最严重的漏洞类型，因为云厂商的全部多租户安全模型都建立在"逃不出去"上。

**发生了什么**：PWN Research 的 Paulos Yibelo 发布 [PwnEscape 第二部](https://pwn.ai/blog/firecracker-escape)：利用第一部披露的宿主物理内存读写原语，攻击者在虚拟机内部先通过 EPT（Extended Page Tables，CPU 硬件维护的"虚拟机地址→真实物理地址"翻译表）定位自己的内存页在宿主机上的位置，再反向扫页表找到 Firecracker 进程，最后精准改写 vCPU 线程进入 KVM 时保存的寄存器帧（pt_regs）——线程从内核返回用户态那一刻，执行的就不再是 Firecracker 的代码，而是攻击者指定的 `write()` 调用，等效于宿主机 root 代码执行。AWS 已发布[安全公告](https://aws.amazon.com/security/security-bulletins/2026-137-2/)称其服务不受影响。

**为什么值得看**：这是近年罕见的**不依赖嵌套虚拟化的通用 Firecracker 逃逸**，而且攻击全程 VM 照常运行、SSH 照常可连——完全静默。跑 Firecracker 的多租户平台（不止 AWS）都该对照检查。

**评论区两边**：**A 方（质疑派）**直言"这是纯 LLM 泔水文"（行文太像 AI 生成），还有人指出这不是新漏洞、只是几周前已披露的 PwnEscape 的实操演示，属于重复提交；**B 方（技术权威派）**由 tptacek（安全圈知名人物）压阵反驳："这是漏洞发现者本人写的、近年第一个通用 Firecracker 逃逸的完整利用链剖析，没有第二信源，本身就是最有价值的内容"——并科普 HN 惯例：原帖没讨论起来的重复提交允许再发。另有架构派借机安利 Nova 微内核路线："别让庞大的 Linux 当 hypervisor，用形式化验证的微内核反过来管 Linux"（被泼冷水：那项目自己都写着"实验性，碎了算你的"）。

### 6. FAA 宣布 2028 年前淘汰空管系统里的软盘（387 分 / 318 评论）

**背景**：美国联邦航空管理局（FAA）的 EIDS/IDS-4 系统负责给空管终端分发气象等关键数据，这套系统 1990 年代初上线、跑在 MS-DOS 上，**至今还在用 3.5 英寸软盘**（容量 1.44MB，大概一张手机照片的三分之一）做数据交换介质。这不是段子，是 FAA 官方文档写的。

**为什么值得看**：这是"关键基础设施技术债"的活标本——不是没钱换，而是安全关键系统"能跑就别动"的保守文化 + 采购流程的惰性，让 1980 年代的介质活到了 2026 年。参照系：软盘淘汰在 FAA 排期表上要 20 年，而你的浏览器两个月一更。

**评论区两边**：**A 方（嘲讽/担忧派）**："我不希望 FAA'以闪电速度'改任何东西，安全必须排在快速升级前面"，且质疑"historic"的公关话术——"把该做的事做了不配叫历史性"；**B 方（反驳派）**指出方向搞反了：老化存储介质本身就是安全隐患（软盘会消磁、驱动器停产、会读软盘的人快退休完了），拖着不换才是拿安全赌博。还有技术考古派挖出细节：其实早有人提议用"软盘模拟器+SD 卡"糊弄过去，以及一个扎心观察——如果 1.44MB 就装得下空管关键数据，"各位开发者，你的 App 真的需要 800MB 安装包吗？"

### 7. RealPage 算法定价案落幕：房东们赔租客 3.6 亿美元（170 分 / 65 评论）

**背景**：RealPage 是一家给房东提供"收益管理系统"（RMS，Revenue Management System——算法根据市场数据建议每套房该收多少租金）的公司。特别之处：它的建议输入包含**各大房东的非公开数据**（实际成交价、入住率等）。美国司法部指控这等于让竞争对手通过算法"共享底牌"，构成变相价格合谋。

**为什么值得看**：这是"算法合谋"（algorithmic collusion，没人开会、没打电话，但大家用同一个算法看同一份私有数据，效果等同卡特尔）领域金额最大的落地判例之一，给所有做 B 端定价 SaaS 的公司划了条线：你的算法可以看公开市场价，但不能成为私有数据的"洗白通道"。

**评论区两边**：**A 方（追责派）**认为和解就是挠痒痒——RealPage 手里还握着十年的历史定价数据，换汤不换药，"这些公司不会因为一次手腕拍打就停止合谋"；**B 方（市场派）**反驳：禁令后房价高的地方并没有应声下降，说明真正的问题是供给不足而非算法——"这看着根本不像价格操纵，更像供给短缺市场里的价格发现，而起诉他们的政府才是供给不足的始作俑者"。中间有人提问"那算法看公开市场价算不算合谋？"——没人能给出清晰答案，这正是此案留下的最大悬案。

### 8. Anthropic 官方拆解：Agent 的记忆到底是怎么做的（120 分 / 65 评论）

**背景**：AI Agent（能自主执行多步任务的 AI）最大的短板之一是"金鱼记忆"——每次新会话都从零开始。业界通行做法是让 Agent 把重要信息写成 markdown 笔记存起来，但"记什么、怎么整理、何时更新"一直没人系统讲过。

**为什么值得看**：这是头部大厂第一次把 Agent 记忆的工程细节摊开讲，"记什么"的判断力（显著性判断）比"怎么存"更决定效果——对做 Agent 产品的团队是现成的设计参考。
