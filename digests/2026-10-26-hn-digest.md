### 2. Goose：无堆、无 GC、无生命周期标注的"内存安全系统语言"（526 分 / 214+ 评论）

作者是 aardappel（Wouter van Oortmerssen，Cube 引擎、Lobster、FlatBuffers 的作者），Carmack 发推助推。设计激进：**没有堆**，所有动态值内联在编译器管理的数据栈上，作用域结束即释放，百万元素的嵌套结构释放只需一条 store 指令；引用在数组扩容后依然有效；类型化窄链接（1/2/4 字节偏移）让数据结构可以直接写文件再读回。自称 16 个基准里跑赢惯用 C++ 3.3 倍、手调 C++ 1.16 倍、最佳安全 Rust 1.12 倍，内存占用少 1.2-1.9 倍，且无 unsafe、无生命周期语法。
👉 为什么值得看：这是对 Rust 所有权模型的一次正面替代提案，"零标注内存安全 + 比 C 快"如果站得住，是系统编程的大事；就算站不住，设计文档本身也值得一读。
💬 评论区吵点：两极。一边是语言设计爱好者认真讨论数据栈模型；另一边质疑文档是"Claudese"（Claude 腔），要求作者重写成自己的话、说清哪些设计是人的哪些是 AI 的意外，自跑基准的可信度也被打问号。还有人提醒别和 Block 家的 AI agent 框架 goose-docs.ai 重名搞混。

### 4. GPU-unlock：Linux 内核模块解锁 RTX 30 系被锁的算力（319 分 / 74 评论）

Nvidia 在消费级 GA102/103/104/106 芯片上用速率选择器锁了 FP/BF16 FMA 的指令发射率（专业卡是双倍）。这个项目把此前 CMP 解锁器的 V67/PLM 手法包成**早于 Nvidia 驱动绑定的内核模块**：写完速度选择器再做 FLR，驱动无需打补丁、升级驱动也不用重新折腾。实测 3090 Ti 450W 下 BF16 稠密 GEMM 从 87.5 → 157.4 TFLOPS（+80%），TF32 翻倍；LLM prefill 实测提速 14-36%，decode（显存带宽瓶颈）基本无感。已有 Windows 移植版，3060/3070/3080/3090 用户报告大面积成功。
👉 为什么值得看：手里有 30 系卡的可以直接白嫖接近翻倍的矩阵算力，本地跑 LLM 推理/扩散模型的经济账被改写；也是观察 Nvidia 产品线人为切割的活标本。
💬 评论区：作者空降 AMA，氛围罕见地一致叫好（"希望所有 mod 都像你这样不折腾驱动"），调侃"接下来解锁 4090"。争议点在幕后：这种解锁大概率违反 EULA，商用有法律风险；有人提醒 3080 Ti 20GB OEM 版解锁成功但 BF16 仍半速，个体差异存在。

### 5. Cerebras：万亿参数模型怎么跑（311 分 / 90+ 评论）

## 💬 今日吵架冠军：Goose 编程语言

**正方**：无堆数据栈 + 零标注内存安全 + 自测跑赢 C++/Rust，还有 Carmack 转发和 Cube 引擎作者的信誉背书，设计文档里"释放百万元素结构只需一条 store""数据结构可直接落盘"这类想法确实性感，值得认真对待。
