### 1. 我们接管了 ChatGPT 账号：一个分享链接的杀伤力（237 分 / 99 评论）

**背景**：ChatGPT 有两个看似无害的功能——「分享对话」（生成公开链接）和「HTML 预览」（把对话里的代码块渲染成小网页）。为防代码乱来，预览页被关在一个沙箱（sandbox，浏览器里的隔离小房间）中，运行在另一个域名下，理论上碰不到你登录着的主页面。**发生了什么**：安全公司 Parameter 发现，对话里一个普通图表会加载数学库 MathLive，而 MathLive 会在主页面注册一个 postMessage 监听器（postMessage 是浏览器里两个隔离页面互相递纸条的官方通道）。攻击者在预览沙箱里伪造一条 MathLive 格式的消息递出去，主页面的 JavaScript 毫无防备地执行了它——于是攻击者代码直接跑在 chatgpt.com 的已登录会话里，能读你的全部私密对话、上传文件、改账号设置。受害者唯一要做的动作就是点开一个分享链接。OpenAI 定级 P1（最高严重级）并于 10 月 26 日修复，赏金 5000 美元。**为什么值得看**：这是典型的「两个各自安全的功能拼起来不安全」，提醒所有做 Web 的人：postMessage 监听器必须校验消息来源，第三方库可能替你在主页面开了扇窗。**评论区争论**：A 方（不少安全从业者）认为 5000 美元赏金低得离谱——这是能接管任意账号的 P1，对一家号称万亿估值的公司来说九牛一毛，低赏金会劝退未来的报告者，甚至有人激愤地说「不如卖给黑市」；有人补充 Meta 更糟，修了漏洞一分钱不给。B 方反驳：卖漏洞给地下市场在多数国家是犯罪（协助犯罪也是犯罪），伦理和法律不能混为一谈，况且安全研究员 tptacek 有个著名观点——服务端漏洞价值本来就低，因为它很快被修补，攻击窗口短。

### 2. VOLTA 窃密木马：偷完你的数据，再让 AI 给你「估价」（179 分 / 78 评论）

**背景**：infostealer（窃密木马）是一类专门偷浏览器密码、Cookie、加密货币钱包的恶意软件，过去偷完就把原始数据打包卖给下游犯罪分子，由人肉筛选「哪台机器值得深挖」。**发生了什么**：Cisco Talos 披露的 VOLTA-AUTODOXER 把这个筛选环节交给了 LLM。它偷完标准套餐（密码、卡号、SSH 密钥、Discord/Telegram 会话、截图）后，还会用偷来的会话继续挖：搜你的 Gmail 购物收据来推断家庭住址、拉 UberEats 订单、给 Roblox 账号估价。然后把这份「证据包」POST 给 OpenRouter（一个聚合各家大模型的 API 中转站），系统提示词让模型扮演「法医情报分析师」，输出必须包含「这人值多少钱」（按变现价值分低/中/高档）和「这人的 OPSEC」（安全习惯评估）两节。如果模型拒绝，它会自动切换到最多三个模型的备用链——说明作者对「AI 会说教拒答」有充分的工程预期。木马本身自删除、不留攻击者基础设施。**为什么值得看**：这是「AI 当犯罪情报分析师」的早期实锤，攻击者的自动化程度在质变。**评论区争论**：A 方嘲讽「好事，LLM 干这个并不在行」——专用工具比大模型更快更准更便宜，属于蹭热点；B 方反驳说「够用就行」，先跑通再优化是聪明的工程策略，而且恶意软件作者可不会乖乖买正版专用软件。另一条高赞线更沉重：有人担心 Claude Code 这类工具平时就有扫你家目录的习惯（多人现身说法：它找 Terraform 配置时真的会 `find ~`），一旦供应链被投毒，10 秒就能搬空你的数字生活——于是引出「银行/开发/游戏各备一台电脑」还是用 QubesOS/虚拟机隔离的大讨论。

### 3. Northflank 被黑：「假设你所有环境变量都泄露了」（468 分 / 348 评论）

**背景**：Northflank 是 2019 年成立的云平台（PaaS，把「部署运维」打包卖给你的服务，类似 Heroku），最近两年主打「跑 AI agent 的沙箱环境」。**发生了什么**：10 月 30 日起其状态页连发严重安全事件通告：调查仍在进行，但指导方针是「假设所有环境变量已被解密，立即轮换全部密钥」，用户已报告存在平台上的 AI API key 被盗刷（攻击 IP 与 Wiz 安全公司「黑色十月」报告中针对 AI 凭证的攻击潮吻合）。平台随后紧急给所有用户（含免费版）开放审计日志和 MySQL/Redis 密钥轮换。**为什么值得看**：环境变量（存在平台里的密码、API key 等配置）是开发者的命门，一旦平台被黑等于所有客户的钥匙串一起丢；这也是几周内又一家中小云厂商翻车。**评论区争论**：A 方认为这类事件会把企业客户赶回 AWS/Azure 等超大规模云——「没有比大厂被黑更安全的了：大家都被黑，你反而不用背锅」，即现代版「买 IBM 不会被开除」，本质是买责任和 SLA；还有人爆料大厂安全团队资源、渗透测试和内部威胁情报共享根本不是初创公司能比的。B 方反驳：大厂并不真的更安全——Azure 跨租户漏洞多到「惊讶公有云这个概念还存在」（当天首页正好挂着下文第 6 条），而且 PaaS 初创的风险是「双层暴露」（既信初创又信它底下的云），但 AWS/GCP 自己也是地雷阵，配错了照样完蛋，尤其现在还有 AI 自信地教你错误配置。

### 4. Scribd 被黑：泄露通知挤牙膏（318 分 / 118 评论）

**背景**：Scribd 是老牌文档分享/订阅阅读平台（旗下还有 SlideShare、Everand）。**发生了什么**：用户陆续收到邮件：未授权第三方入侵了系统，多数账号泄露基本信息，部分账号泄露信用卡后四位、发卡行、有效期和国家。诡异的是时间线——博客 10 月 1 日就发了「安全事件」说明，但通知邮件分批发，有用户 10 月 30 日才收到，官方 FAQ 只说「分阶段发送」，拒绝解释为什么涉及支付信息还要拖一个月。**为什么值得看**：泄露本身不算新鲜，但「挤牙膏式披露」是数据泄露危机公关的反面教材；评论区有人贴出邮件原文，证实泄露范围确实含支付卡元数据。**评论区争论**：A 方（高赞）对 Scribd 毫无同情——这家公司靠当年「上传即共享」的盗版文档起家，信誉早已透支，「受害者值得同情，公司一滴也不配」；B 方则借题发挥担忧「没人是安全的」：HN 首页天天挂泄露，是不是 AI 降低了攻击门槛？反驳意见认为漏洞本来就一直在那，AI 只是发现漏洞的工具，真正的变化是攻击方先用上了它；也有人说这其实是新常态，公众十年前就对泄露疲劳了——直到有人进监狱或丢工作，否则罚款只会被当作经营成本。顺带一提：HN 管理员 dang 罕见现身，解释了 Tell HN 帖子为什么是浅灰色低对比度（PG 时代的遗产，鼓励发链接而非纯文本），并考虑开放用户自定义 CSS。

### 5. Azure 最薄弱的一环：五个跨租户完全沦陷，赏金 20 万美元（327 分 / 59 评论）

**背景**：多租户云（multi-tenant cloud）= 一栋大楼里住着成千上万家公司的服务器，「租户」就是每家房客；跨租户攻击指 A 房客能打开 B 房客的门，是云安全里最严重的事故类型。Azure Logic Apps 的 API Connections 组件让用户把 Jira、Salesforce、Key Vault 等外部服务接进自动化流程。**发生了什么**：挪威 Binary Security 的研究员 Haakon Wik Gulbrandsrud 发表系列第三篇：这个组件的架构里，共享的 API Management 实例负责「拿你的输入 token 换后端服务的真 token」，只要骗过它的输入校验，任何人都能操作全世界任何人的连接，拿到后端完全访问权——包括跨租户读取 Key Vault（密钥保险柜）和 Azure SQL 数据库。这次一口气报告五个漏洞，全部殊途同归，微软合计付了 20 万美元赏金（参照系：普通白领年薪的一半以上，单个漏洞平均 4 万美元）。更尴尬的是：其中一个漏洞此前被报告过、微软修过，但修复不完整，新研究让旧洞复活。**为什么值得看**：路径穿越+IDOR（越权访问，通过改个 ID 就能看别人数据的漏洞）这类「小学级别」的输入校验错误出现在微软的核心云组件里，而且同一处修了两次都没修干净。**评论区争论**：A 方质问「Azure 跨租户泄露数量遥遥领先，为什么企业还蜂拥而上？」答案还是那句「没人因为买微软被开除」——已付费 Teams/Intune 的企业顺手就用 Azure，加上 FedRAMP 合规光环（尽管 ProPublica 爆料联邦安全专家私下认为微软云「一坨屎」还是照样批准了）；B 方（包括自称微软员工）辩护说微软当年安全流程严格到「耽误发功能」的程度，官僚化恰恰是安全文化的体现，规模效应下大厂仍比小厂强。中间派指出：微软员工内部报漏洞没人理，外人报漏洞拿 20 万——激励机制本身就是歪的。

### 6. Cisco 给 27 岁工程师无限 AI token，重写 98% 的遗留代码（285 分 / 338 评论）

**背景**：遗留代码（legacy code）指公司里跑了很多年、没人敢动的老代码——像老城区的违章建筑群，拆了怕塌，不拆又碍事。业界几十年共识是「永远不要大规模重写」，因为老代码里埋着多年积累的 bug 修复和特例，文档从来没跟上。**发生了什么**：《财富》报道，Cisco 总裁 Jeetu Patel 把一个「藏在组织角落里做无关紧要事情」的 27 岁前创业者 Paddy 挖出来，给他无限 AI token 和一句「Go nuts（放开干）」，让他主导重写 Cisco 98% 的遗留代码；Patel 还借此抨击「Gen Z 不能吃苦」的论调，称这名年轻人是「劲量兔子」。**为什么值得看**：这是目前公开报道里最大规模的「AI 重写整个公司代码库」豪赌，成了 AI 编程能力边界的一次全民公投。**评论区争论**：A 方（怀疑派，占上风）指出文章根本没解释「为什么 98% 的代码需要重写」——重写历来是软件工程经典自杀方式，老代码里的「脏东西」很多是没写进文档的业务特例，AI 没有上下文分辨哪些 bug 其实是必须保留的行为（「重写 FORTRAN 到 Rust，难道要把每个 bug 都复刻一遍？」），连 Python 去掉 GIL 这种有全世界最聪明脑袋盯着的重写都磨了十年；还有人质疑这就是总裁的 PR 故事。B 方（乐观派）认为 AI 恰好改变了重写的经济学：前沿模型极度擅长保持 API 契约不变、自动写穷尽测试用例、做到 100% 覆盖率、逐个记录老代码的边缘情况——以前重写贵在人月，现在 token 无限供应；「对重写的恐惧是前 AI 时代的肌肉记忆」。中间派提醒：真要重写也该用绞杀榕模式（strangler fig，一块一块替换而不是一次性推倒）。

## 💬 今日吵架冠军：Cisco 让 AI 重写 98% 的遗留代码——壮举还是自杀？

338 条评论吵成一片，是今日分歧最实质的话题（ChatGPT 赏金之争吵的是钱，这个吵的是「AI 到底能不能干软件工程里最难的活」）。

**A 方（怀疑派）的道理**：大规模重写是软件工程史上著名的坟场，Joel Spolsky 二十年前就写过《Things You Should Never Do》。核心论据是：老代码的价值恰恰藏在那些看起来像屎的部分——十年间为某个大客户加的特例、某个只有凌晨三点才触发的竞态条件的补丁，全都没写进文档。AI 看不到这些上下文，重写出来的「干净代码」会在生产环境把这些坑原样踩一遍。高赞评论给了个绝妙反例：如果 AI 重写真这么灵，Python 去掉 GIL（全局解释器锁，让 Python 多线程跑不满多核的历史包袱）这个有全世界顶级工程师盯着、目标明确的重写，为什么磨了这么多年？还有人指出《财富》通篇没回答「为什么 98% 需要重写」，怀疑这整个故事就是 Cisco 高管的招聘 PR。

**B 方（乐观派）的道理**：反对重写的经济学前提变了。以前重写贵在人月——要人读懂旧代码、写测试、逐步迁移；现在 token 近乎免费，而前沿模型恰好是「保持 API 契约不变」的偏执狂：可以让它先给旧代码生成 100% 覆盖率的特征测试（characterization tests，把现有行为原样锁住的测试），再对着测试重写，每个边缘情况都被强制记录。有从业者称自己亲眼见过 AI 重写成功的「一堆高知名度案例」（被追问举例时没能给出，这是 B 方最弱的环节）。他们的结论是：「对重写的恐惧是前 AI 时代的肌肉记忆。」

**我的倾向**：偏 A 方，但给 B 方留一条缝。理由：① B 方的「特征测试锁行为」方案在理论上成立，但前提是你能为旧系统写出覆盖其真实行为的测试——而遗留系统的经典困境恰恰是「没人说得清它的完整行为」，测试本身也是 AI 对着代码猜的，等于用同一个上下文盲区自我验证；② Cisco 是卖网络设备的公司，它的遗留代码大量涉及硬件兼容和协议怪癖，属于「特例密度」最高的那一类，最不适合当 AI 重写的旗舰案例；③ 但我也同意 B 方一点：AI 确实把「小规模、带测试、绞杀榕式」的渐进重写成本打下来了几个数量级——问题不在 AI 能不能重写代码，而在管理层把「98%」当口号喊出来时，工程上的渐进主义就已经死了。值得追踪：六个月后如果 Cisco 敢晒事故率数据，我改判。
